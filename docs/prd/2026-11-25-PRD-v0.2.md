## 1. 产品定义

### 1.1 一句话

**一个能在安卓手机和 Windows 电脑上使用的私人资料库：看到什么丢进去，以后凭模糊记忆也能翻出来。**

### 1.2 它是什么

- 一个**收集器**：文章、视频、图文、图片、文件、链接，统一入口
- 一个**保险箱**：内容落在自己手里，原网页删了也不影响
- 一个**检索器**：记得片段、记得主题、记得日期、什么都不记得，四条路都能走
- 一个**会主动翻旧账的东西**：把旧内容重新推到你面前，而不是等你去整理

### 1.3 它不是什么

| 不是 | 原因 |
|---|---|
| 笔记软件 | 不做富文本编辑器。只存、只找，不做创作 |
| 待办工具 | 不需要任务、截止日期、提醒 |
| 团队知识库 | 单人使用，无协作、无权限体系、无分享 |
| 浏览器书签替代品 | 书签只能按标题和网址搜，这是它最大的问题 |
| 又一个"需要先搭系统"的工具 | 打开就能用，不存在"先设计分类体系"这一步 |

### 1.4 成功的判据

三个月后，任意一条成立即算成功：

1. 想找一条半年前存的东西，**10 秒内找到**
2. 某天闲下来会**主动打开翻**，而不是被迫整理
3. 存一条东西的**动作 ≤ 3 次点击**
4. 某条原网页已经 404，但这里**还能看到当时存了什么**

## 2. 用户与使用时刻

### 2.1 用户画像

| 项 | 内容 |
|---|---|
| 数量 | 1 人 |
| 设备 | Windows 电脑 + 安卓手机。**没有 Mac、没有 iPhone** |
| 技术背景 | 非技术，需要 AI 辅助才能维护 |
| 现有习惯 | 内容散落在浏览器书签、微信收藏、相册、聊天记录里，**基本找不回来** |
| 核心诉求 | 不想要"需要养"的工具，想要"丢进去就行"的工具 |

### 2.2 六个使用时刻（"场景"的最终落地）

> 这不是分类，是**打开应用的理由**。产品要保证这六个时刻都能被满足。

| # | 时刻 | 用户在想什么 | 产品要给什么 |
|---|---|---|---|
| S1 | 要做点什么 | "我要写个东西 / 做个方案，找点参考" | 按主题捞素材，跨类型一起出 |
| S2 | 卡住了 | "这事我不会，之前存过教程" | 方法、步骤、工具 |
| S3 | 找一个以前看过的 | "就那篇讲 XX 的，标题想不起来了" | 按内容片段搜 |
| S4 | 没事干 | "随便翻翻有什么" | 随机漫游、时间轴 |
| S5 | 要给别人看 | "把上次那个发给对方" | 单条分享 / 导出 |
| S6 | 要做个决定 | "之前看过的那个对比，找出来" | 按主题聚合 + 对比视图 |

### 2.3 反场景（不该用它做的事）

- **不该用它写笔记和长文**——写作用别的工具，这里只负责"存和找"
- **不该用它做项目管理**——没有状态流转、没有截止提醒
- **不该要求它替代搜索引擎**——它只搜你存过的东西

## 3. 核心设计原则

| # | 原则 | 说明 | 反面 |
|---|---|---|---|
| DP1 | **存的时候不要求用户做决定** | 只判断它是什么，其余全自动 | 每存一条弹窗让你选分类 → 三周后弃用 |
| DP2 | **分类是机器的事，修正才是人的事** | 自动判，判错一键改，改完记住 | 让用户从零建立分类体系 |
| DP3 | **内容必须落在自己手里** | 正文、封面、摘要都存一份，不依赖原网页存活 | 只存 URL → 半年后一片 404 |
| DP4 | **结构藏在自动里** | 四积木（类型/属性/标签/查询），用户只感知前三层 | 让用户维护一棵复杂的目录树 |
| DP5 | **质量优先于速度** | 不为快而砍抓取完整度、摘要质量；但交互永不阻塞 | 为了"秒开"只存个链接 |
| DP6 | **宁可留空，不生产垃圾** | AI 拿不准就不打标签，进"没归好类的" | AI 硬猜 → 200 个近义标签 |

## 5. 非功能需求

### 5.1 性能原则

> 按用户明确要求修订：**质量优先，性能做到不拖累效果即可。**

| # | 原则 |
|---|---|
| NF1 | **交互永不阻塞**：点保存，界面立即出现占位卡片，用户可以继续操作；抓取与 AI 处理全部在后台 |
| NF2 | **不为快而砍质量**：抓取完整度、摘要质量、标签准确度优先于响应速度。抓得全比抓得快重要 |
| NF3 | **不设多用户指标**：单人使用，不设 QPS、并发数、P95 延迟这类服务端预算，那是给多用户产品准备的 |
| NF4 | **唯一必须量化的**：搜索响应。几千条数据内要"按下就出结果"（感知上无等待），因为搜索是你最常用的动作 |

### 5.2 兼容性

| 项 | 要求 |
|---|---|
| 手机 | 安卓 Chrome 76+（Web Share Target 最低版本要求） |
| 电脑 | Windows 10/11，Chrome / Edge 最新版 |
| 不支持 | iOS、Safari（无 Mac，无法构建与测试） |

### 5.3 安全

- 全部流量 HTTPS
- 单账号登录，服务端校验会话
- 对象存储不公开读，文件通过签名 URL 访问
- 导出功能保证数据可携带（不锁定）

### 5.4 可维护性

- 单一语言（TypeScript），不为性能引入第二种语言
- 不引入需要长期运维的自建服务（搜索引擎、消息队列、缓存），能省则省
- 抓取层按站点做成"适配器"，单站点失效不影响整体

### 5.5 成本控制

| 项 | 策略 |
|---|---|
| AI 调用 | 摘要 + 标签 + 图片描述，每条 1-3 次调用；几千条约几元到几十元/月 |
| 封面存储 | 统一压缩，单张 ≤ 200KB |
| 视频 | 默认不存原文件，只存封面 + 字幕 + 摘要 |
| 快照 | 压缩 HTML，单条 100-500KB |

## 6. 信息架构

详见设计文档第五章。此处仅摘要：

```
一条内容
├── 类型（6+1，固定）        → 它是什么
├── 属性（字段集合）          → 它什么状态
├── 标签（两级，可多挂）      → 它关于什么
└── 查询（保存的筛子）        → 我什么时候要看它
```

**关于"入口"的修订**：v0.0 曾规划 6 个固定入口（要做方案 / 想学个东西 / 想买点什么…）。经确认**目前无法想清楚**，故本版取消固定入口，改为：**用户通过保存筛子（M5-05）自行固化入口**。用两三个月后，真实需要的入口会自己浮现。

---

## 7. 数据需求

详见设计文档第六章。核心表：

`items`（内容主体）· `tags`（标签）· `item_tags`（多对多，带 AI 置信度）· `queries`（筛子）· `files`（文件引用）· `jobs`（后台任务队列）

三条硬要求：

1. 每张表都有 `created_at`，便于排查
2. 内容删除用软删除（`deleted_at`），30 天后才物理清除
3. 标签的 `origin` 字段必须区分 `ai` / `user`，方便将来整体撤销 AI 标签

## 9. 验收标准

| # | 条件 |
|---|---|
| V1 | 粘贴一条公众号链接，卡片带封面 + 摘要 + 标签出现在列表。**时间不限，但必须成功**；连续 10 条成功率 ≥ 8 条 |
| V2 | 点保存后，列表**立即**出现占位卡片，操作不被阻塞（不出现全屏 loading） |
| V3 | 存够 500 条后，搜索"按下就出结果"，无感知等待 |
| V4 | 手机上从微信分享一条内容到入库，**≤ 3 次点击** |
| V5 | 任意一条记录，在详情页能看到它的正文或摘要；**原链接 404 也不影响** |
| V6 | 导出文件包含全部字段与标签关系，结构完整、人可读，可被将来的导入器直接使用（**本版只做导出，不做导入**） |
| V7 | 判错类型时改一次，同来源的同类内容不再判错；规则可见、可删 |
| V8 | 连续使用一周，**没有一次"必须整理才能继续用"的时刻** |
| V9 | AI 没把握时不硬猜，留空进"没归好类的"；该筛子里没有堆积超 30 条未处理 |

**V8 与 V9 是全篇最重要的两条**：它们检查这东西有没有变成第二个负担。

## 10. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 微信分享面板不显示 PWA ⚠️ | 手机入口体验打折 | **M1 阶段第一件要实测的事**；不通则退化为"复制→粘贴" |
| 公众号反爬 ⚠️ | 抓不到正文，摘要质量下降 | 降级为「链接」类型；实测后再定方案（可能需无头浏览器） |
| B站/抖音接口变动 ⚠️ | 封面、字幕抓不到 | 抓取层做成适配器，单站点故障不影响其它 |
| 安卓 `share_target` 收文件失败 ⚠️ | 手机无法分享图片 | 已明确排除在 MVP 外（M1-10 归 P2） |
| AI 标签判错 | 需人工修正 | 一键改 + 规则记忆；不追求准确率，只追求改起来便宜 |
| 存了不看 | 库变成黑洞 | M7-04/05 必须在第一批上线 |
| 云服务免费额度耗尽 | 突然要付费 | 封面压缩、不存视频原文件、导出保证能走 |
