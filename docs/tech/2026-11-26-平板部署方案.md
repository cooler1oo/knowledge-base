## 一、结论

**能当主力，但必须接受四个让步。** 这四个不是"可能有点影响"，是确定的代价：

| # | 让步 | 影响 | 是否有解 |
|---|---|---|---|
| 1 | **无头浏览器用不了** | 小红书、抖音这类 SPA 页面抓不到正文，降级为"链接" | 无解（Android 上没有可用的 Playwright）。公众号、知乎、B站不受影响——这三类占日常大头 |
| 2 | **后台可能被系统杀掉** | 某天早上发现服务没起来 | 有解但需三项设置（第五节），联想 ZUI 比原生安卓更激进 ⚠️ 需实测 |
| 3 | **没有公网 IP** | 在外面（4G/5G）访问不到，除非开 Tailscale | 有解（第六节），代价是手机常驻 VPN 或用一个虚拟网卡 |
| 4 | **长期插电，电池会鼓** | 一两年后电池报废 | 部分机型有"电池保护/充电上限"，需在设置里确认 ⚠️ |

**四个让步里，只有第 1 个是不可逆的能力缺失**。其余三个都是配置问题。

|---|---|---|
| `postgresql` | 18.7 | 数据库 |

| `caddy` | 2.11.9 | 反向代理 + 自签证书 |
| `git` | 2.56.1 | 拉代码 |
| `openssh` | 10.6p2 | 局域网调试用 |
| `termux-services` | 0.13-1 | 开机自启（Termux 没有 systemd，用这个） |
| `termux-api` | 0.60.0 | 唤醒锁、通知 |
| `python-lxml` | 6.1.3 | HTML 解析（trafilatura 的硬依赖） |
| `python-pillow` | 13.0.0 | 图片压缩 |
| `python-bcrypt` | 有 | 密码哈希 |
| `python-numpy` | 2.5.5 | 备用 |

包索引共 3,043 个包（`packages.termux.dev` 的 aarch64 主源）。

### 2.2 Termux 源里**没有**、且 PyPI 也没有 Android 轮子的

这一格是决定架构的地方。Android 用的是 bionic libc，PyPI 上的 `manylinux` 轮子是给 glibc 编译的，**装不上**；没有轮子就要现场编译，而这些包要么是 Rust、要么依赖系统库，编译基本失败。

| 包 | 类型 | PyPI 有 Android 轮子？ | Termux 有预编译？ | 结论 |
|---|---|---|---|---|
| `psycopg` / `psycopg2-binary` | C | 否 | **否** | 换驱动 |
| `pydantic-core` | Rust | 否 | 否 | FastAPI 用不了 |
| `argon2-cffi-bindings` | C | 否 | 否 | 换 bcrypt |
| `markupsafe` | C | 否 | 否 | Flask 用不了 |
| `playwright` | 无 Android 支持 | — | — | 关闭 |

### 2.3 纯 Python、可直接 pip 装的（已核实 `py3-none-any` 轮子）

`starlette 1.10.0`、`uvicorn 0.54.0`、`pg8000 1.31.6`、`httpx 0.28.1`、`trafilatura 2.4.0`、`jieba 0.42.1`、`apscheduler 3.11.3`、`pydantic 2.14.4`（纯 Python 层可用，但底层 `pydantic-core` 不可用，因此不能用 FastAPI）。

## 三、四处依赖替换（每处都要付代价）

| 原方案 | 换成 | 为什么 | 代价 |
|---|---|---|---|
| FastAPI | **Starlette** | FastAPI 依赖 `pydantic-core`（Rust），装不上 | 失去自动生成 OpenAPI 文档、失去请求体自动校验。校验改用 Starlette 中间件 + 手写 zod 等价物；接口契约本来就写在文档里，不依赖自动生成 |
| psycopg (v3) | **pg8000** | psycopg 是 C 扩展 | pg8000 是纯 Python 实现，性能略低（单条插入差距在毫秒级，单用户无感）；不支持 `COPY` 的某些高级用法，本项目不用 |
| argon2id | **bcrypt**（Termux 包） | argon2 的 bindings 是 C | OWASP 把 bcrypt 列为"遗留系统可用，work factor ≥ 10"。本项目取 **cost=12**，单用户场景足够。⚠️ 这是安全性的降级，不是等价替换 |
| Playwright | **关闭**（`RENDER_ENABLED=false`） | Android 无可用方案 | SPA 页面（小红书/抖音）只能存链接。公众号/知乎/B站为静态或 API，不受影响 |

**一处不变**：中文检索方案（jieba 分词 + Postgres tsvector + 二字词兜底）完全不变，因为 `jieba` 是纯 Python，Postgres 是原生安装。

## 四、部署步骤（在平板上跑，每步带验收）

### 4.0 前置：装 Termux 与两个插件

**必须从 F-Droid 装，不要用 Google Play 版**——Play 版已停止更新，包管理器会失效。

| 装什么 | 从哪 | 作用 |
|---|---|---|
| Termux | F-Droid | 主程序 |
| Termux:Boot | F-Droid | 开机自启（不加这个，重启后要手动敲命令） |
| Termux:API | F-Droid | 唤醒锁、发通知（可选但建议） |

装完先打开 Termux:Boot **一次**（它要靠这一次启动注册自启），然后关掉。

### 4.1 基础环境

```bash
pkg update -y && pkg upgrade -y
pkg install -y postgresql python caddy git openssh termux-api termux-services python-lxml python-pillow python-bcrypt
```

**验收**：`psql --version` 输出 `psql (PostgreSQL) 18.7`；`caddy version` 输出 `v2.11.9`；`python --version` 输出 `Python 3.14.x`。

### 4.2 唤醒锁与存储权限（这一步不做，后面全是白做）

```bash
termux-wake-lock
termux-setup-storage
```

- `termux-wake-lock` 会在通知栏挂一条常驻通知，**不能划掉**，划掉等于解除锁，系统随时会杀。
- `termux-setup-storage` 会弹权限框，允许后 `~/storage` 可访问相册（将来分享图片要用）。

**验收**：通知栏有 Termux 的常驻通知；`ls ~/storage` 能看到 `shared` 等目录。

**还要做一步（在系统设置里，不在命令行）**：设置 → 应用 → Termux → 电池 → 选"不受限制"（ZUI 的路径可能是"应用启动管理"→ Termux → 关掉自动管理）。
⚠️ 这一步无法用命令验证，只能靠"放一晚，早上看服务还在不在"。

### 4.3 Postgres

```bash
mkdir -p $PREFIX/var/lib/postgresql
initdb $PREFIX/var/lib/postgresql
pg_ctl -D $PREFIX/var/lib/postgresql start
createuser --superuser kb
createdb -O kb kb
```

**验收**：`psql -d kb -c "select version();"` 打印出版本行。

**开机自启**（Termux 没有 systemd，用 termux-services 的 runit）：

```bash
mkdir -p $PREFIX/var/service/postgresql
cat > $PREFIX/var/service/postgresql/run <<'EOF'
#!/data/data/com.termux/files/usr/bin/sh
exec pg_ctl -D $PREFIX/var/lib/postgresql start -w
EOF
chmod +x $PREFIX/var/service/postgresql/run
sv-enable postgresql
```

⚠️ `pg_ctl start` 会阻塞或立即退出，runit 更适合用 `postgres` 前台进程。若 `sv` 起来后进程反复重启，改用：

```bash
cat > $PREFIX/var/service/postgresql/run <<'EOF'
#!/data/data/com.termux/files/usr/bin/sh
exec postgres -D $PREFIX/var/lib/postgresql
EOF
```

（两种写法都要在设备上试，以能稳定跑住的为准。这是唯一需要现场试错的地方。）

### 4.4 应用

```bash
cd ~ && git clone <你的仓库地址> kb && cd kb
python -m venv .venv && source .venv/bin/activate
pip install starlette uvicorn pg8000 httpx trafilatura jieba apscheduler python-multipart
```

**验收**：`python -c "import starlette, pg8000, trafilatura, jieba; print('ok')"` 输出 `ok`。

⚠️ 如果 `trafilatura` 装的时候试图编译 `lxml`，说明它没识别到系统里的 `python-lxml`。处理：先 `pip install --no-deps trafilatura`，再单独装它的纯 Python 依赖 `courlan htmldate charset-normalizer urllib3`。

### 4.5 Caddy + 自签证书

```bash
caddy trust          # 把 Caddy 的根证书装进系统信任库（需要手动确认）
caddy run --config Caddyfile
```

Caddyfile：

```
:8443 {
    tls internal
    reverse_proxy 127.0.0.1:8000
}
```

**为什么用 8443**：Android 上非 root 无法监听 80/443 以下端口。8443 是可用端口。

**验收**：手机浏览器打开 `https://<平板IP>:8443/api/health`，无证书警告（因为已 `caddy trust`），返回 `{"ok":true,"dbOk":true}`。

⚠️ `caddy trust` 在 Android 上能否成功装进系统信任库，未验证。若失败，改走 Tailscale 的 `*.ts.net` 真证书（第六节），或接受浏览器告警一次。

## 五、当主力的关键：保活

四道保险，缺一道就会某天早上发现服务没了。

| # | 措施 | 命令/位置 | 验证方式 |
|---|---|---|---|
| 1 | 唤醒锁 | `termux-wake-lock`（写进 `.bashrc` 或开机脚本） | 通知栏常驻通知在 |
| 2 | 电池优化白名单 | 系统设置 → Termux → 不受限制 | 放一晚看是否还活着 |
| 3 | 开机自启 | Termux:Boot 的 `~/.termux/boot/start.sh` | 重启后不敲命令直接访问 |
| 4 | 进程守护 | `termux-services`（runit） | `sv status` 显示 run |

`~/.termux/boot/start.sh`：

```bash
#!/data/data/com.termux/files/usr/bin/sh
termux-wake-lock
sv-enable postgresql
sv-enable caddy
sv-enable kb
```

**验收（必须做）**：重启平板 → 等 2 分钟 → 不做任何操作，直接在电脑浏览器打开 `https://<平板IP>:8443/api/health`。返回 200 才算保活成功。

## 六、在外面怎么访问（没公网 IP）

| 方案 | 做法 | 代价 |
|---|---|---|
| **Tailscale（推荐）** | 平板、手机、电脑各装一次，登录同一账号；用 `https://<平板名>.<tailnet>.ts.net` 访问 | 手机要常驻 VPN（可以只对私有网段生效） |
| Cloudflare Tunnel | 平板跑 `cloudflared`，映射到公网子域 | 流量过 Cloudflare；需要域名（你不注册域名，排除） |
| 直接放弃外网 | 只在宿舍 WiFi 内用 | 出门存不了东西 |

**结论：Tailscale**。它免费额度是 6 用户、设备不限（官方定价页），对本项目够用。开启 HTTPS 后能给 `*.ts.net` 签发真证书，**自签证书那一套可以整个不用**，浏览器和 APK 都不会有告警。

⚠️ Tailscale 的 `*.ts.net` 证书需要管理台开启 HTTPS + MagicDNS，且证书 90 天需续期（用 Caddy 的 Tailscale 集成可自动续）。

## 七、备份（22:30，不是 03:00）

宿舍 23:30 断电，平板靠电池能撑，但**不能假设它一定撑住**。备份必须在断电前完成。

```bash
# ~/.termux/boot/ 之外，另建一个定时任务
cat > ~/backup.sh <<'EOF'
#!/data/data/com.termux/files/usr/bin/sh
D=$(date +%F)
pg_dump -d kb | gzip > ~/storage/shared/kb-backup/$D.sql.gz
find ~/storage/shared/kb-backup -name '*.sql.gz' -mtime +14 -delete
EOF
chmod +x ~/backup.sh
```

配合 `termux-job-scheduler`（Termux:API 提供）每天 22:30 跑一次，落到平板存储的 `kb-backup/` 目录；再让平板自带的云同步（联想云/百度网盘）同步这个目录，就有了异地副本。

**验收**：手动跑一次 `~/backup.sh`，`ls ~/storage/shared/kb-backup/` 有当天的 `.sql.gz`，且 `gunzip -c 该文件 | head` 能看到 SQL 内容。

## 八、验收清单（全过才算"能当主力"）

| # | 项目 | 通过标准 |
|---|---|---|
| 1 | 服务在跑 | `curl -k https://127.0.0.1:8443/api/health` 返回 `ok:true` |
| 2 | 局域网可访问 | 电脑浏览器打开 `https://<平板IP>:8443` 出现登录页，无证书告警 |
| 3 | 重启自恢复 | 重启平板，2 分钟后不操作即可访问 |
| 4 | 过夜不死 | 放一晚（含 23:30 断电），早上仍可访问 |
| 5 | 存一条公众号 | 抓取成功，有封面 + 摘要 + 标签 |
| 6 | 中文搜索 | 搜"矩阵"能命中相关条目 |
| 7 | 备份可恢复 | 删库 → 从 `kb-backup/` 恢复 → 抽查 3 条内容完整 |
| 8 | 外网可访问 | 手机关 WiFi 用流量，通过 Tailscale 打开 |

第 4 项是"能不能当主力"的真正判据。**它不通过，其余全过也没用。**

## 九、风险与退路

| 风险 | 可能性 | 影响 | 退路 |
|---|---|---|---|
| ZUI 杀后台 | **高** ⚠️ | 服务夜里消失 | 加电池白名单 + 唤醒锁；仍不行则该 ROM 不适合当主机 |
| 系统升级后 Termux 包失效 | 中 ⚠️ | 需重装依赖 | 升级前记录 `pkg list-installed`；用 `termux-change-repo` 换镜像 |
| 电池鼓包 | 中（长期插电） | 硬件损坏 | 查"电池保护"开关；或每天手动断电几小时 |
| 平板拿走时服务断 | 确定 | 出门带走就没服务 | 备用机（旧手机/电脑）跑同一份代码，数据库从备份恢复 |
| `caddy trust` 失败 | 中 ⚠️ | 浏览器告警 | 走 Tailscale 真证书 |
| 抓不到 SPA 页面 | 确定 | 小红书/抖音只能存链接 | 无解，接受 |

## 十、这一步的实际定位

**平板当主力是可行的，但它不是"免费的小服务器"，而是"用一台随时可能被系统干预的消费设备承担服务器职责"。**

判断它是否够用的唯一标准是第八节第 4 项：**放一晚，早上还在不在。** 连续七天都在，就可以放心用；某天开始反复消失，说明这台设备（或这个 ROM）不适合，换 T3（年付 VPS，≈¥10/月）比继续调设置划算。

**建议节奏**：先在平板上跑到第八节前 3 项通过，用一周，再决定要不要把数据正式迁进去。不要一上来就把唯一的数据放进去。
