## 0. 一页摘要

### 0.1 系统是什么

一台**联想 Y900 13 平板**（8GB+6GB / 256GB）当常驻服务端，跑 Termux + proot Debian；手机装 APK 负责系统分享入口；电脑用浏览器访问。三端通过 **Tailscale** 组网，不需要域名、不需要备案、不暴露公网。

**核心链路**：手机分享一条抖音 → 平板抓取（标题/封面/原图或原视频/时长/作者/发布时间）→ AI 出摘要与标签 → 存入 Postgres → Meilisearch 建索引 → 列表里出现卡片。

### 0.2 与技术选型相关的八个决定

| # | 决定 | 一句话理由 | 详见 |
|---|---|---|---|
| D1 | 部署在平板，proot Debian（非 Termux 原生） | 多个 C 扩展只有 glibc 轮子；Android 内核不向非 root 暴露 namespace，Docker 不可用 | §2、§7.1 |
| D2 | 抖音抓取用 **ParseHub**，不自写 | 实测一个调用拿到 `duration=991100` 毫秒与 3 张 1440 宽原图，省 120 行自写，且**不需要 Chromium** | §4 |
| D3 | 检索用 **Meilisearch**（aarch64 静态包） | Charabia 内置中文分词，省自写 jieba+tsvector+三级兜底 | §3.2、§8 |
| D4 | 后端 **Python 3.12 + Starlette**（不用 FastAPI） | `pydantic-core` 是 Rust，Android 无轮子 | §7.2 |
| D5 | 数据库 **Postgres 18**（Debian 源装，不用 Termux 包） | Termux 包是 bionic 编译，proot Debian 里装不上 | §7.3 |
| D6 | DB 驱动 **pg8000**，密码哈希 **bcrypt** | `psycopg` 与 `argon2-cffi-bindings` 都是 C 扩展，无 Android 轮子 | §7.2 |
| D7 | 不套用 karakeep 等现成产品 | 8 个同类产品全都不满足；karakeep 有 6 条致命问题（其中「Termux 跑不了 Docker」与「官方 App 不认 fork 类型」是否决项） | §3.1、§9 |
| D8 | 复用 12 个组件，只自写 4 块 | 用户明确要求「能复用就别造」；自写部分都有「现成方案查过且不合用」的记录 | §3.2 |

### 0.3 当前状态：哪些验过了，哪些没验

| 类别 | 数量 | 说明 |
|---|---|---|
| **已实测通过** | 16 项 | 抖音视频/图文解析、原视频下载、原图下载、依赖可安装性（静态分析）等，见 §12.1 |

## 1. 约束（方案必须满足的条件）

| # | 约束 | 对设计的强制影响 |
|---|---|---|
| C1 | 单人自用，无协作、无权限体系 | 不做多用户、不做 RBAC、不做 CRDT；冲突用后写覆盖 |
| C2 | 只有 Windows + 安卓，无 Mac / 无 iPhone | 不考虑 iOS；APK 侧载，不上应用商店 |
| C3 | 非技术背景，出问题要能靠 AI 修 | 组件越少越好；不引入需要人工解三方合并的技术债（这条否决了 fork karakeep） |
| C4 | 成本几元到几十元/月 | 硬件用现有平板，零新增；AI 按量，必须有月度上限 |
| C5 | **平板持续在线**（用电池，不受宿舍断电影响） | 服务可常驻平板；断电只影响电脑 |
| C6 | 不注册域名、不备案 | Tailscale 组网；Caddy 用 `tls internal` 自签 |
| C7 | **主力内容是抖音**（视频 + 图文；文章极少） | 抓取是必需项而非增强项；抖音抓不通则整个产品不成立 |
| C8 | 能复用就别造 | 每个技术实现前必须做开源调研，由 `tools/doc_checks/reuse.py` 强制 |
| C9 | 本会话只设计，不施工 | 本文不含执行动作 |

**C7 的推论（必须写清）**：抖音是唯一主力来源，因此它的抓取质量决定了产品的及格线。而实测显示抖音的**可读文本只有标题一句**——这意味着检索主要靠**标题 + 封面 + 时间**，而不是正文语义。这一点在设计检索与 UI 时必须体现（§8.2）。

### 2.1 为什么是 proot Debian 而不是 Termux 原生

| 环境 | libc | 能装 ParseHub 吗 | 结论 |
|---|---|---|---|
| Termux 原生 | bionic | ❌ 多个 C 扩展（opencv / cryptography / pydantic-core）无 bionic 轮子 | 不可用 |
| **proot Debian** | glibc | ✅ manylinux aarch64 轮子可直接用 | **采用** |

**代价（必须写清）**：

| 代价 | 量级 | 缓解 |
|---|---|---|
| 磁盘 | Debian rootfs 约 400MB + 依赖约 800MB ≈ 1.2GB | 256GB 可忽略 |
| 内存 | proot 本身约 50MB 额外开销 | 可忽略 |
| 性能 | proot 用 ptrace 拦截系统调用，IO 密集型约慢 5–15% | 单用户场景无感知 ⚠️ 未实测 |
| 保活 | Termux 被 Android 杀则整条链路中断 | 四道保险（§2.3） |

### 2.2 端口与可达性

| 服务 | 监听 | 谁能访问 |
|---|---|---|
| Caddy | `0.0.0.0:8443` | Tailscale 网段（`100.64.0.0/10`）+ 本机 |
| api | `127.0.0.1:8000` | 仅本机（Caddy 反代） |
| meilisearch | `127.0.0.1:7700` | 仅本机 |
| postgres | `127.0.0.1:5432` | 仅本机 |

**为什么不用 80/443**：Android 非 root 无法绑定 1024 以下端口。8443 是唯一现实选择，代价是 URL 带端口号——**对 APK 无感**（地址写死在应用内），只在电脑浏览器上手输一次。

### 2.3 保活：四道保险（缺一不可）

| # | 措施 | 不做会怎样 |
|---|---|---|
| 1 | `termux-wake-lock` 常驻，前台通知不可划掉 | 息屏 10 分钟后进程被冻结 |
| 2 | Termux 电池优化设为「不受限制」 | 系统在低电量时优先杀它 |
| 3 | 装 Termux:Boot 并手动打开一次 | 重启后不自启，必须手动敲命令 |
| 4 | `termux-services`（runit）守护 api / worker | 单个进程崩了不会自己起来 |

⚠️ **联想 ZUI 的后台管理比原生安卓更激进**，这四道能否扛住必须真机验证（G6）。**若 G6 反复失败，结论是「这台设备不适合当主机」，换 T3 年付 VPS（约 ¥10/月），不要继续调设置。**

## 4. 抖音抓取设计（全案最关键）

### 4.1 结论：用 ParseHub，不自写

`z-mio/ParseHub`（206★，MIT，2026-11-21 仍在更新）是 Python 社交媒体聚合解析库，**支持抖音视频与图文，且已处理完反爬细节**。

**实测对比（同两条真实链接）**：

| 项目 | 自写 CDP 方案 | ParseHub |
|---|---|---|
| 代码量 | 约 120 行（CDP 连接、等待、注入 JS、下载） | **3 行** |
| 视频标题 | ✅ | ✅ 一致 |
| 视频播放地址 | ✅ | ✅ 一致，且带 `backup_urls` 备用域名 |
| **视频时长** | 需自己解析 `_ROUTER_DATA`（毫秒） | ✅ **`media.duration = 991100`**（与手写完全一致） |
| 图文图片 | 3 张 1080 宽 | ✅ **3 张 1440 宽**（分辨率更高） |
| 类型判定 | 自己按 URL 判断 | ✅ **`type = 'video' / 'image'`** |
| 需要 Chromium | **需要**（约 400MB 内存） | ❌ 不需要 |

**关键：ParseHub 不需要浏览器**，为抖音专装 Chromium 并常驻 400MB 内存的代价不必付。

### 4.3 用法

```python
from parsehub import ParseHub

ph = ParseHub()
result = ph.parse_sync(share_url)          # 支持短链与整段分享文案

body = {
    "type": result.type,          # 'video' | 'image'
    "title": result.title,
    "name": result.name,          # 已清洗的文件名
    "platform": result.platform,
    "content": result.content,    # 正文；抖音为空
}

if result.type == "video":
    body["video_url"] = result.media.url
    body["video_backup_urls"] = result.media.backup_urls
    body["cover_url"] = result.media.thumb_url
    body["duration_sec"] = (result.media.duration or 0) // 1000
    body["width"] = result.media.width
    body["height"] = result.media.height
else:
    body["images"] = [
        {"url": img.url, "w": img.width, "h": img.height}
        for img in result.media
    ]
```

### 4.9 退路：自写 CDP + `_ROUTER_DATA`

**只在 G2c 失败时启用。** 核心原则：**数据从 `window._ROUTER_DATA` 取，不从 DOM 取**——DOM 会掺入评论区与相关推荐。

```python
ROUTER_JS = r"""
(() => {
  const findAweme = (o, depth) => {
    if (depth > 8 || !o || typeof o !== 'object') return null;
    if (o.awemeId || o.aweme_id || o.desc !== undefined) return o;
    for (const k of Object.keys(o)) {
      const r = findAweme(o[k], depth + 1);
      if (r) return r;
    }
    return null;
  };
  const a = findAweme(window._ROUTER_DATA, 0);
  if (!a) return null;
  return {
    desc: a.desc ?? null,
    author: (a.author || {}).nickname ?? null,
    createTime: a.createTime ?? null,
    duration_ms: (a.video || {}).duration ?? 0,
    images: (a.images || []).map(i => ({
      url: (i.url_list || [])[0] ?? null, w: i.width, h: i.height,
    })).filter(i => i.url),
    video_url: ((a.video || {}).play_addr || {}).url_list?.[0] ?? null,
    hashtags: (a.textExtra || []).map(t => t.hashtagName).filter(Boolean),
    stats: {
      digg: (a.statistics || {}).digg_count ?? 0,
      comment: (a.statistics || {}).comment_count ?? 0,
    },
  };
})()
"""

async def extract_douyin_fallback(url: str) -> dict:
    kind = "note" if "/note/" in url else "video"
    page = await cdp.open_page(url, mobile_ua=True)
    await page.wait(12)                      # 实测需 8–13s

    a = await page.eval(ROUTER_JS)
    if a is None:
        raise ExtractFailed("_ROUTER_DATA 不存在，页面可能被风控")

    out = {
        "kind": kind,
        "title": (a["desc"] or "").strip(),
        "author": a["author"],
        "published_at": epoch_to_date(a["createTime"]),
        "likes": a["stats"]["digg"],
        "hashtags": a["hashtags"],
    }
    if a["duration_ms"]:
        out["duration_sec"] = a["duration_ms"] // 1000
    if kind == "video" and a["video_url"]:
        out["video_bytes"] = await download(
            a["video_url"], referer="https://www.douyin.com/")
    if kind == "note":
        out["images"] = [
            await download(img["url"], referer="https://www.douyin.com/")
            for img in a["images"][:9]
        ]
    await page.close()
    return out
```

**四条硬约束**：

| 约束 | 原因 | 违反后果 |
|---|---|---|
| 从 `_ROUTER_DATA` 取，不从 DOM 取 | DOM 掺入评论区与相关推荐 | 存进别人的内容 |
| 图片数用 `images.length`，不用 `<img>` 计数 | DOM 数到 12 个，实际只有 3 张 | 存一堆无关图 |
| 移动 UA | 桌面 UA 无 `<video>` | 抓不到视频 |
| 封面/原图/视频当场下载 | URL 带 `x-expires` 签名 | 过期 403 |

### 5.1 类型判定（自写，不足 20 行）

```python
def decide_type(meta: ExtractResult) -> str:
    # 域名修正规则优先，高于自动判断（PRD M3-08）
    if rule := domain_rule(meta.source_domain):
        return rule
    if meta.kind == "video" or meta.duration_sec:
        return "video"
    if len(meta.images) >= 3 and meta.word_count < 300:
        return "image_text"
    if meta.word_count >= 300:
        return "article"
    if meta.images and not meta.images[0].is_cover_only:
        return "image"
    if meta.file_bytes:
        return "file"
    return "link"          # 6+1 里的那个 +1：抓取失败或判不出来
```

## 6. 数据模型

单人使用，不做协作，**不用 CRDT**；冲突用后写覆盖。**Postgres 为唯一权威源**，不做本地全量缓存（MVP 不做离线）。

### 6.1 表结构（8 张）

```sql
-- 枚举用 CHECK 而不是 ENUM 类型：改枚举值不需要 ALTER TYPE，迁移更容易
CREATE TABLE items (
  id             bigserial PRIMARY KEY,
  type           text NOT NULL CHECK (type IN
                   ('article','image_text','video','image','file','link')),
  url            text,                          -- 图片/文件可为空
  title          text NOT NULL DEFAULT '',
  author         text,
  source_domain  text NOT NULL,
  cover_key      text,                          -- 自有存储的 key，不是外链
  summary        text,                          -- AI 摘要 ≤100 字
  content_text   text,                          -- 正文/字幕全文，用于检索
  word_count     int  NOT NULL DEFAULT 0,
  duration_sec   int,
  published_at   timestamptz,
  saved_at       timestamptz NOT NULL DEFAULT now(),
  status         text NOT NULL DEFAULT 'unread'
                   CHECK (status IN ('unread','reading','read','archived')),
  rating         smallint CHECK (rating BETWEEN 1 AND 5),
  props          jsonb NOT NULL DEFAULT '{}',   -- 每类型的附加属性
  deleted_at     timestamptz,
  created_at     timestamptz NOT NULL DEFAULT now(),
  updated_at     timestamptz NOT NULL DEFAULT now()
);

CREATE INDEX items_saved_at_idx   ON items (saved_at DESC) WHERE deleted_at IS NULL;
CREATE INDEX items_type_idx       ON items (type)          WHERE deleted_at IS NULL;
CREATE INDEX items_domain_idx     ON items (source_domain);
CREATE INDEX items_status_idx     ON items (status)        WHERE deleted_at IS NULL;
CREATE INDEX items_rating_idx     ON items (rating)        WHERE rating >= 4 AND deleted_at IS NULL;

CREATE TABLE tags (
  id         bigserial PRIMARY KEY,
  name       text NOT NULL,
  parent_id  bigint REFERENCES tags(id) ON DELETE RESTRICT,
  color      text,
  is_preset  boolean NOT NULL DEFAULT false,
  created_at timestamptz NOT NULL DEFAULT now()
);

-- 同级重名禁止：同一父节点下 name 唯一；根节点用 coalesce 处理 NULL
CREATE UNIQUE INDEX tags_sibling_name_idx
  ON tags (coalesce(parent_id, 0), name);

-- 两级约束：父节点本身必须是一级（parent_id IS NULL），否则拒绝
CREATE OR REPLACE FUNCTION tags_enforce_two_levels() RETURNS trigger AS $$
BEGIN
  IF NEW.parent_id IS NOT NULL THEN
    IF (SELECT parent_id FROM tags WHERE id = NEW.parent_id) IS NOT NULL THEN
      RAISE EXCEPTION '标签只允许两级，% 已是二级标签', NEW.parent_id;
    END IF;
  END IF;
  RETURN NEW;
END $$ LANGUAGE plpgsql;

CREATE TRIGGER tags_two_levels
  BEFORE INSERT OR UPDATE OF parent_id ON tags
  FOR EACH ROW EXECUTE FUNCTION tags_enforce_two_levels();

CREATE TABLE item_tags (
  item_id    bigint NOT NULL REFERENCES items(id) ON DELETE CASCADE,
  tag_id     bigint NOT NULL REFERENCES tags(id)  ON DELETE CASCADE,
  origin     text NOT NULL CHECK (origin IN ('ai','user')),
  confidence real CHECK (confidence BETWEEN 0 AND 1),
  PRIMARY KEY (item_id, tag_id)
);

CREATE TABLE queries (
  id          bigserial PRIMARY KEY,
  name        text NOT NULL,
  filter_json jsonb NOT NULL,        -- 结构化筛选条件，白名单编译后下发
  icon        text,
  sort_order  int NOT NULL DEFAULT 0,
  pinned      boolean NOT NULL DEFAULT false,
  created_at  timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE files (
  id          bigserial PRIMARY KEY,
  item_id     bigint NOT NULL REFERENCES items(id) ON DELETE CASCADE,
  storage_key text NOT NULL UNIQUE,
  mime        text NOT NULL,
  size_bytes  bigint NOT NULL,
  kind        text NOT NULL CHECK (kind IN ('cover','original','snapshot')),
  created_at  timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX files_item_idx ON files (item_id, kind);

CREATE TABLE jobs (
  id          bigserial PRIMARY KEY,
  item_id     bigint NOT NULL REFERENCES items(id) ON DELETE CASCADE,
  state       text NOT NULL DEFAULT 'pending'
                CHECK (state IN ('pending','running','done','failed')),
  step        text NOT NULL CHECK (step IN ('fetch','summarize','tag','ocr')),
  error       text,
  attempts    smallint NOT NULL DEFAULT 0,
  run_after   timestamptz NOT NULL DEFAULT now(),
  created_at  timestamptz NOT NULL DEFAULT now(),
  updated_at  timestamptz NOT NULL DEFAULT now()
);
-- 幂等：同一条目的同一步骤，未完成时只允许一条
CREATE UNIQUE INDEX jobs_pending_uniq
  ON jobs (item_id, step) WHERE state IN ('pending','running');
CREATE INDEX jobs_pickup_idx ON jobs (run_after) WHERE state = 'pending';

CREATE TABLE domain_type_rules (
  domain     text PRIMARY KEY,
  type       text NOT NULL CHECK (type IN
               ('article','image_text','video','image','file','link')),
  created_at timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE settings (
  key        text PRIMARY KEY,
  value      jsonb NOT NULL,
  updated_at timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE users (
  id            bigserial PRIMARY KEY,
  username      text NOT NULL UNIQUE,
  password_hash text NOT NULL,                 -- bcrypt cost=12
  created_at    timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE sessions (
  token_hash text PRIMARY KEY,                 -- 存哈希，不存明文 token
  user_id    bigint NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  expires_at timestamptz NOT NULL,
  created_at timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX sessions_expiry_idx ON sessions (expires_at);
```

**为什么 `jobs` 要单独一张表**：保存必须「秒回」。写 `items` + 写 `jobs` 后立即返回 202，抓取与 AI 处理异步做；失败可重试，失败原因要让用户看得见（PRD M2-10）。

### 6.2 三条必须写进 DDL 的业务约束

| 约束 | 落在哪里 | 为什么不能只靠应用层 |
|---|---|---|
| 类型只能是 6+1 种 | `items.type` 的 `CHECK` | 应用层漏校验会写入脏数据，检索与渲染全崩 |
| 标签只能两级 | `tags_enforce_two_levels` 触发器 | 挂第三级会让左侧树的遍历逻辑无限递归 |
| 同任务不重复入队 | `jobs_pending_uniq` 部分唯一索引 | 并发点两次保存会抓两遍，浪费且可能触发风控 |

### 6.3 存储布局

```
data/
├── pg/                        # Postgres 数据目录（restic 备份）
├── media/
│   ├── cover/<hash>.webp      # 封面，统一转 webp，长边 ≤1280
│   ├── orig/<hash>.<ext>      # 原图 / 原视频
│   └── snapshot/<hash>.html   # monolith 整页归档
└── backups/                   # restic 仓库位置（外置或网盘挂载）
```

**为什么用 hash 做文件名**：同一条内容重复抓取时自然去重；也避免原始文件名里的中文与特殊字符在 proot 下出问题。

### 8.2 搜索的降级阶梯（重要）

因为抖音的可读文本只有标题一句，**检索的主战场是标题**，不是正文。因此搜索按三级降级：

| 级 | 机制 | 覆盖什么 | 何时用 |
|---|---|---|---|
| L1 | Meilisearch 全文（标题 + 摘要 + 正文 + 标签 + 作者） | 正常情况 | 默认 |
| L2 | Meilisearch 前缀 + 拼写容忍 | 用户记错一个字 | L1 返回 0 条时 |
| L3 | Postgres `ILIKE '%词%'` 扫标题 | Meilisearch 挂了，或中文分词不理想 | L1/L2 都 0 条，或 Meilisearch 不可用 |

**这个阶梯由 G3 关卡决定实际启用哪几级**：若 Meilisearch 对两字词「矩阵」的召回正常，L3 仅作故障兜底；若不正常，L3 提升为常驻路径。

### 8.3 POST /api/items 的请求与响应

```jsonc
// 请求
{ "url": "https://v.douyin.com/xxx/", "raw_text": "可选，分享文案原文" }

// 响应 202
{ "id": 1234, "state": "pending", "deduped": false }
```

**行为**：

1. 解析 URL（从分享文案里提取短链）
2. 按 `url` 查重（规范化后）；命中则返回已有 id 且 `deduped: true`
3. 写 `items`（`type` 先用 `link` 兜底，`title` 先用域名），写 `jobs(step='fetch')`
4. **立即返回 202**，不等待抓取

### 8.4 鉴权

| 项 | 做法 |
|---|---|
| 形式 | HttpOnly + Secure + SameSite=Lax Cookie，值是不透明随机串 |
| 存储 | `sessions.token_hash` 存 SHA-256，**不存明文** |
| 有效期 | 30 天，滑动续期 |
| APK 内 | Capacitor 的 Cookie 管理，登录一次长期有效 |
| 单账号 | 首个注册者即唯一用户；关闭后续注册 |

## 9. 为什么不用现成产品（结论摘要）

8 个同类产品的完整对比在 §3.1。**karakeep 是最接近的一个，六条否决理由**：

| # | 问题 |
|---|---|
| 1 | 覆盖度指标偷换（标签级匹配 vs 契约级逐条满足） |
| 2 | **移动端版本倒挂**：官方 App 不认识 fork 新增的类型，而采集入口就是那个 App |
| 3 | **Termux 跑不了 Docker**：Android 内核不向非 root 暴露 namespace |
| 4 | fork 核心枚举是破坏性迁移，贯穿 zod→Drizzle→tRPC→OpenAPI→SDK→web→扩展→MCP→移动端 |
| 5 | 「1GB 内存」是 idle 观测值，非预算值 |
| 6 | 上游升级使 rebase 成为经常性支出（0.33→0.34 即会话表迁移 + Chrome 镜像换代） |

**保留其架构参考**：资产存储 / Search / Queue 的插件化抽象值得借鉴，但不套用产品。

### 11.2 架构约束（写成检查，不写进文档）

| 约束 | 检查方式 | 为什么用检查而不是注释 |
|---|---|---|

### 11.3 反向测试（验证检查本身有效）
