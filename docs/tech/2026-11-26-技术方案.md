## 1. 你的问题逐条回答

### 1.1 图文能抓全吗 —— 已用真实链接验证

**结论：能抓全，且必须走 `_ROUTER_DATA` 而不是 DOM。**

测试样本：`https://v.douyin.com/j-hfjsvi7ms/` → `aweme_id 7668961791830369521`（`schema_type=37` 即图文）

| 抓取方式 | 能拿到什么 | 实测输出 |
|---|---|---|
| **DOM（`body.innerText`）** | 只有标题 + 评论区 + 相关推荐，**混入了大量无关内容** | `bodyLen: 614`，但正文只有 `happy new year` |
| **`window._ROUTER_DATA`** | **结构化的完整数据** | `desc` / `author` / `createTime` / `images[]`（含宽高）全部拿到 |

`_ROUTER_DATA` 的实测输出（60,190 字节）：

```json
{
  "desc": "happy new year  #龙族 #随笔 #作家江南",
  "author": "迎着阳光盛大逃亡",
  "createTime": 1785542400,
  "imgCount": 3,
  "imgs": [
    {"w":1080,"h":1362},
    {"w":1080,"h":1367},
    {"w":1080,"h":1391}
  ],
  "videoDur": 0
}
```

**三个关键发现**：

| # | 发现 | 影响 |
|---|---|---|
| 1 | **DOM 的 `body.innerText` 会污染数据** | 图文页 `bodyLen: 614` 里混了 6 条「相关推荐」的标题和 3 条评论。如果直接拿 innerText 当正文，会存进别人的内容 |
| 2 | **`_ROUTER_DATA` 有原图，DOM 只有缩略图** | DOM 拿到的是 `540:q75` 压缩图（29,646 字节）；`_ROUTER_DATA` 是 `1080:q80` 原图（**83,388 字节，2.8 倍**） |
| 3 | **`desc` 是完整文案，但没有长正文** | 这条笔记本身就是一句话 + 3 张图，`desc` 只有 22 字。**不是抓取失败，是内容如此** |

**图文页的图片数说明**：DOM 里数到 12 个 `<img>`，但 `_ROUTER_DATA` 里只有 3 张。**DOM 的数字是假的**——它把头像、相关推荐封面也算进去了。以 `_ROUTER_DATA.images` 为准。

### 1.1.1 原图验证

```
原图 URL（1080×1362, q80）下载：
http=200  type=image/webp  size=83388  (82KB)

缩略图对照（540×q75）:
http=200  type=image/webp  size=29646  (29KB)
```

**结论：原图可下载，分辨率是 DOM 版的 2 倍。**

### 1.1.2 抖音文章少，多图文

你指出「抖音文章少，多图文」。实测支持这个判断：`/note/` 页的 `desc` 字段就是全部文字，没有单独的长文章字段（`_ROUTER_DATA` 里搜不到 `article` 或 `content` 长文本字段）。

**所以设计按图文的形态走**：`desc`（文案）+ `images[]`（原图列表），不需要为「长文章」单独设计。

### 1.2 视频：能存原视频吗

**能。已实测下载成功。**

```
完整视频 URL（从 <video>.currentSrc 取）:
https://m.douyin.com/aweme/v1/playwm/?video_id=v0300fg10000c2egtqtovkemgno0u7o0&ratio=720p&line=0

curl 结果:
http=200  type=video/mp4  size=4076253  (3.9MB)
```

1. 从渲染后的 `<video>.currentSrc` 取完整 URL，不能自己拼
2. 请求必须带 `Referer: https://www.douyin.com/`

### 1.4 时长拿不到（待解决）

`video.readyState` 为 0，说明视频流未加载，所以 `duration` 是 `null`。三个候选方案，**均未验证**：

1. 页面内 `video.load()` 后等 `loadedmetadata` 事件
2. 从页面内嵌的 `RENDER_DATA` 找
3. 下载后用 `ffprobe` 读文件（最可靠，多一次 IO）

列为 **G2c 关卡**，必须在真机上试出来。

### 1.5 摘要质量低，根因是什么

**不是模型差，是可摘的文本太少。**

抖音视频页的全部可读文本：

```
标题：#杨超越 小小水手带你去远航❤️
描述：与标题相同
正文：无（视频本身没有文字）
```

AI 摘要的输入只有一句话，输出只能是这句话的同义改写。**换任何模型都一样**——信息量只有这么多。

**三条改善路径**：

| 路径 | 效果 | 成本 |
|---|---|---|
| ASR 语音转文字 | 真正解决：把视频里说的话提出来 | 按分钟计费；本地 whisper 在平板算力上 ⚠️ 需实测 |
| 评论区摘要 | 评论区常有内容概括 | 额外抓取，可能触发风控 |
| 接受现状 | 靠标题+封面+时间检索 | 零成本 |

**这里要修正我 v3.0 的一处夸大**：你要的是「凭模糊记忆找回」，那么**标题 + 封面 + 时间**已经够用，摘要只是锦上添花。所以「摘要质量低」对你实际使用的影响，没有我说得那么大。

## 4. 抖音抓取设计

### 4.0 结论先行：直接用 ParseHub，不自写

**这是本轮最重要的发现，推翻了我前几版自己写抓取器的做法。**

`z-mio/ParseHub`（206★，**MIT**，2026-11-21 仍在更新）是一个 Python 社交媒体聚合解析库，**支持抖音视频与图文**，且已处理完所有反爬细节。

### 4.0.1 实测对比：自写 vs ParseHub

| 项目 | 我自写的 CDP 方案 | ParseHub |
|---|---|---|
| 代码量 | 约 120 行（含 CDP 连接、等待、注入 JS、下载） | **3 行** |
| 视频标题 | ✅ | ✅ 一致 |
| 视频播放地址 | ✅ | ✅ 一致（且带 `backup_urls` 备用域名） |
| **视频时长** | 需自己解析 `_ROUTER_DATA`（毫秒） | ✅ **`media.duration = 991100`**（与我手写结果完全一致） |
| 图文图片 | 3 张 1080 宽 | ✅ **3 张 1440 宽**（分辨率更高） |
| 类型判定 | 自己按 URL 判断 | ✅ **`type = 'video' / 'image'`** 自动给出 |
| 备用地址 | 无 | ✅ `backup_urls` |
| 需要 Chromium | **需要**（约 400MB 内存） | ❌ 不需要 |

**关键：ParseHub 不需要浏览器。** 我上一版方案要为了抖音专门装 Chromium 并常驻 400MB 内存——**这个代价根本不必付**。

## 4.5 【已被 4.0 取代】原自写 CDP 方案

以下内容保留作技术参考，**实际实现不采用**。

### 4.5.1 三条路径实测

| 路径 | 结果 | 报错原文 |
|---|---|---|
| yt-dlp `DouyinIE` | ❌ | `Fresh cookies (not necessarily logged in) are needed` |
| f2 `ABogus` 签名 | ❌ | `403 Blocked by ArgusSecurityPlugin Uifid Not Found` |
| **CDP + 移动 UA** | ✅ | 6 个字段拿到 |

**必须移动 UA**：桌面 UA 下 `body.innerText` 仅 366 字符，拿不到 `<video>`。

### 4.5.2 抓取流程

**核心原则：数据从 `_ROUTER_DATA` 取，不从 DOM 取。** DOM 会掺入评论区与相关推荐（实测 `bodyLen:614` 里大半是别人的内容）。

```python
# 从页面 window 上的结构化数据取字段（实测 _ROUTER_DATA 含完整 aweme 对象）
ROUTER_JS = r"""
(() => {
  const findAweme = (o, depth) => {
    if (depth > 8 || !o || typeof o !== 'object') return null;
    if (o.awemeId || o.aweme_id || o.desc !== undefined) return o;
    for (const k of Object.keys(o)) {
      const r = findAweme(o[k], depth + 1);
      if (r) return r;
    }
    return null;
  };
  const a = findAweme(window._ROUTER_DATA, 0);
  if (!a) return null;
  return {
    desc: a.desc ?? null,
    author: (a.author || {}).nickname ?? null,
    createTime: a.createTime ?? null,
    duration_ms: (a.video || {}).duration ?? 0,
    images: (a.images || []).map(i => ({
      url: (i.url_list || [])[0] ?? null, w: i.width, h: i.height,
    })).filter(i => i.url),
    video_url: ((a.video || {}).play_addr || {}).url_list?.[0] ?? null,
    hashtags: (a.textExtra || []).map(t => t.hashtagName).filter(Boolean),
    stats: {
      digg: (a.statistics || {}).digg_count ?? 0,
      comment: (a.statistics || {}).comment_count ?? 0,
    },
  };
})()
"""

async def extract_douyin(url: str) -> dict:
    kind = "note" if "/note/" in url else "video"
    page = await cdp.open_page(url, mobile_ua=True)
    await page.wait(12)                       # 实测需 8-13s

    a = await page.eval(ROUTER_JS)
    if a is None:                             # 兜底：_ROUTER_DATA 不存在时退 DOM
        a = await page.eval(DOM_FALLBACK_JS)

    out = {
        "kind": kind,
        "title": (a["desc"] or "").strip(),
        "author": a["author"],
        "published_at": epoch_to_date(a["createTime"]),
        "likes": a["stats"]["digg"],
        "hashtags": a["hashtags"],
    }

    # 视频：duration 单位是毫秒
    if a["duration_ms"]:
        out["duration_sec"] = a["duration_ms"] // 1000
    if kind == "video" and a["video_url"]:
        out["video_bytes"] = await download(a["video_url"],
                                            referer="https://www.douyin.com/")

    # 图文：images 就是原图列表（1080 宽），不是缩略图
    if kind == "note":
        out["images"] = [
            await download(img["url"], referer="https://www.douyin.com/")
            for img in a["images"][:9]
        ]

    await page.close()
    return out
```

**四条硬约束**：

| 约束 | 原因 | 违反后果 |
|---|---|---|
| **从 `_ROUTER_DATA` 取，不从 DOM 取** | DOM 掺入评论区与相关推荐 | 存进别人的内容 |
| **图片数用 `images.length`，不用 `<img>` 计数** | DOM 数到 12 个，实际只有 3 张（头像/推荐封面混入） | 存一堆无关图 |
| 移动 UA | 桌面 UA 无 `<video>` | 抓不到视频 |
| 封面/原图/视频当场下载 | URL 带 `x-expires` 签名 | 过期 403 |

### 4.3 时长提取（已解决）

`_ROUTER_DATA` 里 `video.duration` 是**毫秒**（实测该图文样本为 `0`，因为它是图文无视频）。视频样本需再验一次单位，但对图文已确认字段存在。

**DOM 的 `video.duration` 仍为 `null`**（流未加载），所以**必须走 `_ROUTER_DATA`**，这条不再是待解决项。

## 5. 为什么不用 karakeep

六条致命问题（经对抗审查确认）：

| # | 问题 |
|---|---|
| 1 | 覆盖度指标偷换（标签级 vs 契约级） |
| 2 | 移动端版本倒挂：官方 App 不认识 fork 新增类型，而采集入口就是那个 App |
| 3 | Termux 跑不了 Docker（Android 内核不向非 root 暴露 namespace） |
| 4 | fork 核心枚举是破坏性迁移，贯穿 zod→Drizzle→tRPC→OpenAPI→SDK→web→扩展→MCP→移动端 |
| 5 | 「1GB 内存」是 idle 观测，非预算值 |
| 6 | 上游升级使 rebase 成为经常性支出（0.33→0.34 即会话表迁移 + Chrome 镜像换代） |

**保留其架构参考**：资产存储/Search/Queue 的插件化抽象值得借鉴，但不套用产品。
