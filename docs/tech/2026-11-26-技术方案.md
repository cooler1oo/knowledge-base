## 1. 必须先解决的一个矛盾（这是全文重点）

### 1.1 矛盾是什么

把你的四条事实摆在一起，它们互相打架：

| 事实 | 来源 |
|---|---|
| 主力内容是**抖音**，人在外面刷 | 你明确说过 |
| 服务放在**宿舍平板**，23:30–06:00 断电 | 你明确说过 |
| **不注册域名、不备案、不开公网** | 你明确说过 |
| 不接受每月几十元固定开销 | 你明确说过 |

**这四条同时成立时，「在外面刷到抖音 → 立刻存进知识库」这件事不可能做到。** 原因很直接：

- 手机在 4G/5G 上，服务在宿舍局域网内，中间没有公网入口 —— 手机找不到服务。
- 就算找了局域网，23:30 之后宿舍断电，服务不存在。
- 而 23:30 之后恰恰是你刷抖音最集中的时间。

**这不是性能问题，也不是优化能解决的，是主链路断了。**

### 1.2 三条出路，必须选一条

| 路线 | 做法 | 代价 | 手机在外面能否立刻存 |
|---|---|---|---|
| **A. 服务放公网** | 境外小主机（Oracle 免费层 / 低价 VPS），IP 直连 + 自签证书 | 要么零成本但需注册绑卡；要么约 ¥10/月 | ✅ 能 |
| **B. 手机本地先存，回家再同步** | 手机 App 建本地队列，连上宿舍 WiFi 时批量上传 | 需自写一个 App；「立刻看到摘要」变成「回家才看到」 | ⚠️ 能存，但看不到处理结果 |
| **C. 接受只在宿舍用** | 服务在平板，回家才存 | 零成本；等于放弃「在外面刷到就存」这个核心场景 | ❌ 不能 |

**我的判断**：A 是唯一能满足你原始需求的路线。你之前否决 Oracle 是因为不想绑卡、觉得流程麻烦；但把上面的矛盾摊开后，**A 的「麻烦」比 C 的「功能失效」小得多**。

**这一条需要你拍板，我不能替你决定。** 你选 A / B / C，后面的设计完全不同。

### 1.3 本文其余部分怎么写

下面按 **A 路线** 展开（因为它最能满足需求），同时标出 B、C 需要改动的地方。如果你选 B 或 C，我按标注改。

## 3. 上一版（v2.0）错在哪

v2.0 提出「直接用 karakeep 当底座」，经对抗审查后被推翻。**审查提出的 37 条问题里，有 6 条是致命的**，我逐条核实后确认成立：

| # | 问题 | 为什么致命 |
|---|---|---|
| 1 | **「覆盖 28/41」是标签级匹配，不是契约级** | 它算「搜索」命中，但 P0 要的是中文可检索质量；算「视频归档」命中，但 P0 要的是抖音能归档。同一个词被偷换，这个比例不可比 |
| 2 | **移动端版本倒挂** | 官方安卓 App 不认识 fork 新增的类型与视图。你在手机上看到的是 unknown 或错乱。**采集入口就是这个 App，等于新增类型在真实链路上不可达** |
| 3 | **Termux 跑不了 Docker** | karakeep 只发 Docker 镜像；安卓内核不向非 root 暴露 namespace。proot 能跑单进程，但承载不了「自带 init + 多容器互联」的编排。**这条路径不存在，不是难一点** |
| 4 | **断电时段覆盖主力时段** | 见第 1 节。这是全案最硬的一条 |
| 5 | **fork 核心枚举 = 破坏性迁移** | `BookmarkTypes` 被 zod → Drizzle → tRPC → OpenAPI → SDK → web → 扩展 → MCP → 移动端贯穿。4 值扩到 7 值是改契约的根，不是加页面。上游一次升级（0.33→0.34 把会话从 JWT 迁到 DB 表、Chrome 镜像换代、worker 失败改为整进程退出）就够一个 fork 解三天冲突 |
| 6 | **内存数字是闲置观测值当预算值** | 「1GB」是社区 idle 观测；Meilisearch 索引期有 Memory exhausted 的公开 issue。8GB 平板扣掉 Android 常驻后可用内存需实测（M0 记 `dumpsys meminfo`） |

**我自己加的第七条**：v2.0 把「抖音交给自写抓取器」写成「一行缺口」，实际那是一个需要长期跟平台对抗的子系统（cookie 生命周期、DASH 分片、短时效签名、风控）。**低估了一个数量级。**

**结论**：karakeep 作为**整套产品**套用，不成立。但它的**架构决策和组件**值得复用——这是第 4 节的内容。

## 4. 修订后的技术路线

### 4.1 复用边界的重新划定

审查的第 35 条点出了我漏掉的第三条路：**复用它验证过的组件和架构，而不是 fork 它的产品。**

| 层 | 复用什么 | 怎么复用 | 为什么不整套用 |
|---|---|---|---|
| 正文抽取 | **trafilatura**（7,175★，Apache-2.0，纯 Python） | 直接作为库调用 | 通用库，本来就该单独用 |
| 网页归档 | **monolith**（15,619★，0BSD，Rust） | 单文件二进制，命令行调用 | 同上 |
| 抖音签名 | **f2 的 `abogus.py`**（2,754★，Apache-2.0） | 参考其纯 Python 实现 | 实测签名能生成，只是被 `uifid` 挡（见 5.2） |
| 视频下载 | **yt-dlp**（Unlicense） | 直接调用 | B站等站点可用 |
| 中文检索 | **Meilisearch**（单独部署） | 单容器，不走 karakeep | 中文分词用 Charabia（jieba），但要自己配词典 |
| 浏览器抓取 | **CDP 直连 Chromium** | 自写约 80 行 | 已实测可行（5.1） |
| **产品层** | **不复用** | 自己写 | 见第 3 节六条致命问题 |

**代价对比**：

| | 套用 karakeep（v2.0） | 复用组件（v3.0） |
|---|---|---|
| 从零到可用 | 3 周（若 Termux 能跑，但它不能） | 约 6–8 周 |
| 维护负担 | 跟随上游 rebase + 解冲突 | 组件各自升级，无冲突 |
| 移动端 | 官方 App 不认识新类型 | 自己写，完全可控 |
| 主线能否成立 | 断电时断 | 取决于你选 A/B/C |

**诚实的结论**：v3.0 比 v2.0 工作量大，但**v2.0 的「3 周」是假的**——它建立在一个跑不起来的部署假设上。

## 5. 抖音：三条路径的实测与结论

### 5.1 实测记录（2026-11-26，本机 Chrome 138，x86）

| 路径 | 结果 | 报错原文 / 证据 |
|---|---|---|
| yt-dlp 的 `DouyinIE` | ❌ | `ERROR: [Douyin] xxx: Fresh cookies (not necessarily logged in) are needed`；源码 TODO 明写需运行验证挑战生成签名 cookie |
| f2 的纯 Python `ABogus` 签名 | ❌ | 签名生成成功（`a_bogus=...` 拼入 query），服务端返回 `403 Blocked by ArgusSecurityPlugin Uifid Not Found`。补 `ttwid`（注册接口可取，长度 127）后仍同一 403 |
| **CDP 直连 Chromium + 移动 UA** | ✅ | `<title>` 拿到真实文案；`video.src` 拿到 `m.douyin.com/aweme/v1/play...`；封面 URL `curl` 返回 `http=200 type=image/webp size=21186` |

**关键细节**：桌面 UA 下 `document.body.innerText` 仅 366 字符（导航+页脚），拿不到 `<video>`；**必须移动 UA**。

### 5.2 这条路仍然不轻松

审查第 15、17 条说得对，我必须承认：

| 问题 | 现状 | 影响 |
|---|---|---|
| cookie 生命周期 | 未解决。`uifid` 挡住 API，意味着**必须走浏览器**，长期要靠浏览器上下文维持 | 浏览器常驻内存 |
| 抖音标题多是话题标签 + emoji | 实测标题形如 `#杨超越 小小水手带你去远航❤️` | **AI 摘要近乎空转**——没有正文可读 |
| 无 ASR | 视频语音内容拿不到 | 摘要只能基于标题，质量差 |
| 图文/合集/长视频差异 | 未测 | 可能有分支未覆盖 |

**这条最该说清**：即使抓取成功，**抖音内容的「摘要+标签」质量会明显低于文章**，因为可读文本太少。这不是 bug，是内容形态决定的。PRD M3-02（摘要 ≤100 字）在抖音上产出的多是「标题的同义改写」——这一点列为 G6 关卡实测，不预设结论。

**如果你的核心诉求是「凭模糊记忆找回」，那么靠的其实是标题 + 封面 + 时间，而不是摘要。** 这需要你确认：这个质量可接受吗？

### 5.3 三步退路

| 退路 | 代价 | 启用条件 |
|---|---|---|
| 抓取跑在公网小主机上（A 路线） | 需付费或绑卡 | 选 A |
| 抓取跑在 Windows（白天） | 23:30 后不可用 | 选 C 且接受 |
| 只存链接 + 手填一句话 | 无摘要无封面 | 最差情况 |

## 7. 关键设计（只写与 v1.8 不同的部分）

### 7.1 采集入口：分享 Intent

```xml
<intent-filter>
  <action android:name="android.intent.action.SEND" />
  <category android:name="android.intent.category.DEFAULT" />
  <data android:mimeType="text/plain" />
</intent-filter>
<intent-filter>
  <action android:name="android.intent.action.SEND_MULTIPLE" />
  <category android:name="android.intent.category.DEFAULT" />
  <data android:mimeType="image/*" />
</intent-filter>
```

**为什么是 APK 而不是 PWA**：审查第 27 条指出，无域名 + 纯 HTTP 下 WebAPK 与分享目标不可用；Android 9+ 默认禁明文。APK 内置自签根证书，是这套约束下唯一可靠的分享入口。

### 7.2 检索：先 Meilisearch，不先自研

v1.8 花了一整节论证「jieba + tsvector + 三级兜底」。现在改为**优先用 Meilisearch**，理由：

| | 自研 tsvector | Meilisearch |
|---|---|---|
| 中文分词 | 自己接 jieba | Charabia 内置（jieba 词典） |
| 二字词兜底 | 要写 LIKE 全表扫 | 词典 + typo 容忍自带 |
| 排序质量 | 自己调 `ts_rank_cd` | 内置相关性排序 |
| 维护 | 自己扛 | 上游 |

**但审查第 37 条的补充成立**：Meilisearch 的中文质量不等于「内置 jieba 就好用」，需要配词典。所以：

- **保留自研方案作为 fallback**：如果 Meilisearch 在两字词/长尾上不达标，退回 Postgres FTS + jieba。
- **验证放在 G2 关卡**，不预设结论。

### 7.3 类型判定与修正记忆（自建，仍需写）

这部分 v1.8 的设计成立，保留：

```python
def decide_type(has_video: bool, text_len: int, image_count: int,
                upload_kind: str | None) -> str:
    if upload_kind == "image": return "image"
    if upload_kind == "file":  return "file"
    if has_video:              return "video"
    if image_count >= 3 and text_len < 300: return "image_text"
    if text_len >= 300:        return "article"
    if text_len > 0:           return "image_text"
    return "link"
```

修正记忆：`domain_type_rules(domain, type)`，用户改类型时写入，同域名优先用规则。

## 8. 验证关卡（每关不过不进下一关）

| 关 | 验证什么 | 通过判据 | 不过怎么办 |
|---|---|---|---|
| **G0** | 公网主机能否部署起来（A 路线） | `curl https://IP:8443/api/health` 返回 `dbOk:true` | 换主机或选 C |
| **G1** | 手机 4G 能否访问 | 关 WiFi 用流量打开页面 | 检查防火墙/证书 |
| **G2** | 抖音抓取（公网 IP） | title + 封面 + `video.src` 三者齐全 | 退只存链接 |

| R2 | 纯 Python 签名被 `uifid` 挡（403 原文） | 不能无浏览器抓 | 走 CDP |
| R3 | 抖音必须移动 UA | 写死移动 UA | 已定 |
| R4 | 抖音封面是 `x-expires` 签名 URL | 过期即 403 | 当场下载 |
| R5 | Termux 无法跑 Docker（Android 内核限制） | 平板不能跑容器编排 | 服务放公网 |
| R6 | karakeep 标签扁平、类型枚举贯穿全栈 | fork 代价被低估 | 不 fork 产品 |

### 10.3 关于「AI 能不能修得动」

你这台设备上，故障分两类：

| 类别 | AI 能修 | 例子 |
|---|---|---|
| 配置、日志、单文件逻辑 | ✅ | 端口冲突、证书过期、解析规则失效 |
| 三方合并冲突、语义迁移 | ❌ | 上游升级导致全员登不进、框架版本跃迁 |

**v2.0 的致命错误之一就是让第二类落到了你头上**（fork 上游）。v3.0 不 fork 产品，正是为了让故障都落在第一类。
