## 三、与设计的偏离清单

### 3.1 方案 §4.3 的调用契约写错了 `media` 的形状（需升版）

| 项 | 内容 |
|---|---|
| 方案原文 | `# result.to_dict() → {platform, type, title, content, raw_url, media}`，暗示 `media` 是列表 |
| 实测真相 | `media` 是**三种形态之一**：`list[dict]` / `dict` / `None` |
| 源码依据 | `parsehub/types/result.py:68-83` |

```python
# 源码原文（parsehub/types/result.py）
media: list[dict] | dict | None = None
if isinstance(self.media, Sequence):
    media = [asdict(m) for m in self.media]  # 图文 → 列表
elif self.media:
    media = asdict(self.media)  # 视频 → 单个 dict
```

| 内容类型 | result 类 | `media` 形状 |
|---|---|---|
| 视频 | `VideoParseResult` | `dict`（单个） |
| 图文 | `ImageParseResult` | `list[dict]`（多张） |
| 多视频/视频+图 | `MultimediaParseResult` | `list[dict]` |
| 无媒体 | — | `None` |

**影响**：只按视频写映射代码，遇到图文会 `AttributeError`（对 list 取 `.get()`）。
**处置**：映射层必须做「先判断类型再取值」，不能用一种形状套全部。

### 3.2 `duration` 的单位，源码注释写错了（需回写方案）

| 项 | 内容 |
|---|---|
| 源码注释 | `duration: 视频时长，单位: 秒`（`media_ref.py:33`） |
| 实测值 | `445071` |
| 核对 | 按毫秒 = **7.4 分钟**（符合「第12集讲解」视频）；按秒 = **123.6 小时**（不可能） |
| 结论 | **实际是毫秒**。注释错了，不能照注释写代码 |

**这直接影响 `items.props.duration_sec` 生成列**：库里那个生成列叫 `duration_sec`，
若把毫秒值直接写进 `props.duration_sec`，一条 7 分钟的视频会被记成 445071 秒（5 天）。
映射时必须 `// 1000`。

### 3.3 `ImageRef` 与 `VideoRef` 的字段差异

| 字段 | `ImageRef`（图文） | `VideoRef`（视频） |
|---|---|---|
| `url` / `ext` / `thumb_url` / `width` / `height` | ✅ | ✅ |
| `duration` | ❌ **没有这个字段** | ✅ 有（毫秒，见 §3.2） |
| `backup_urls` | ❌ 没有 | ✅ 有（实测 3 条） |

映射代码取 `duration` 前必须确认是视频，否则 KeyError。

## 四、下一轮（R3 正文）的已知坑

| # | 坑 | 现象 | 防法 |
|---|---|---|---|
| 1 | `media` 三种形状 | 对 list 调 `.get()` 报 `AttributeError` | 映射前先判 `isinstance(media, list)` |
| 2 | `duration` 是毫秒 | 时长被记成 445071 秒 | 写库前 `// 1000`；并补一条单测钉住这个换算 |
| 3 | 图文没有 `backup_urls` / `duration` | `KeyError` | 用 `.get()`，缺失给默认值 |
| 4 | 小红书无 cookie 被风控 | `FallbackError: 被风控拦截` | 需要真实有效链接复验；不要拿编造 ID 的失败当「不支持」 |
| 5 | 单条抓取 10–20 秒 | 同步等待会阻塞 | 抓取放在 worker（R5），API 只入队 |
| 6 | 签名 URL 带 `x-expires` | 过期后 403 | **抓到立刻下载**，不留外链（方案 §4.6） |
| 7 | 探针脚本经三层嵌套引号传参会炸 | `syntax error near unexpected token` | 脚本落盘再执行，不用 `ssh "... python -c \"...\""` |

## 五、诚实标注

✅ **已验证**（每条都有上面的原始输出）
- ParseHub 在平板容器内可导入，`Platform` 25 个
- 真实抖音视频链接能抓到：`title` 非空、`type=video`、`media` 7 个字段、`duration=445071`
- 返回对象的完整属性与方法清单
- `media` 的三种形态由源码 `to_dict()` 确证（不是推测）
- `duration` 实际单位是毫秒（用 7.4 分钟 vs 123.6 小时交叉核对）

⚠️ **未验证**
- 抖音**图文**（`ImageParseResult`）的真实抓取——我用的两条 ID 均为编造，一条 `ContentUnavailableError`、一条不存在。形状由源码确证，但**端到端没跑通**
- **小红书**是否真的可用（被风控拦，但链接本身可疑）
- B站、公众号、知乎、微博等其余 14 个平台
- 抓取峰值内存（方案 §2.5 的预算是否会破）

❌ **失败过的尝试**
- 小红书链接抓取 → `FallbackError: 被风控拦截`
- 手编的抖音图文 ID → `ContentUnavailableError: 作品不可用: core_dep`
- 用 `ssh "python -c \"...\""` 传三段嵌套引号的脚本 → bash 语法错，改为落盘执行
