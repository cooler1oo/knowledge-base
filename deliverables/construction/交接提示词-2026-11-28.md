## 四、五条硬规矩（违反会返工）

1. **跑测试不能加 `cd` 前缀**。外部 Stop 门禁只认「第一段是 `python`/`pytest`」的命令。
   `cd 某目录 && python -m pytest` 会被判成「没跑验证」而反复拦下——项目已因此误判 4 次。
   要在项目根直接跑 `python -m pytest -q`。

2. **本机全绿 ≠ 验过了**。有 131 条用例在本机必然跳过（需要 Postgres）。
   `python -m tools.eng_checks --all` 会明确告诉你「pg 用例 131 条全部跳过」。
   **改 `kb/store/` 或 SQL 相关的代码，必须去平板真库跑一次**（见 §五）。

3. **每条规则先问「能不能变成机器检查」**。能，就写进 `tools/`，不写进文档正文。
   这是项目最核心的工程哲学（AGENTS.md §八）。

4. **不许说「应该/大概/理论上」**。不确定就写 ⚠️ 并说明验证方法。

5. **改代码前先写清根因与证据**。没根因不改码，改完不验证不说完成。

## 六、三个已踩过的坑（别重踩）

1. **`git push` 的代理端口每次会变**。环境变量 `$HTTPS_PROXY` 指向的可能是沙箱自己的代理
   （`sandbox-cli.exe`），到 GitHub 会 502。正确做法是扫一遍监听端口找能通的那个：
   ```bash
   for p in $(netstat -ano | grep "127.0.0.1:" | grep LISTEN | awk '{print $2}' | sed 's/.*://' | sort -un); do
     code=$(curl -s -o /dev/null -w "%{http_code}" --max-time 3 -x "http://127.0.0.1:$p" https://github.com)
     [ "$code" = "200" ] && echo "可用: $p"
   done
   git config http.proxy "http://127.0.0.1:<可用端口>"
   ```
   SSL 握手偶发失败时，同一端口重试一次通常就过。

2. **判断 OpenCV 是否 headless 不能用 `'GUI' in getBuildInformation()`**。
   实测输出是 `  GUI:                           NONE`（冒号后 27 个空格），
   字符串包含判断会误判成「是 GUI 版」。要取出含 `GUI:` 的整行看冒号后的值。

3. **`where (select count(*) from gone) >= 0` 这行 SQL 不是冗余，不许删**。
   它语义恒真，作用是制造求值依赖保证 DELETE 先于 INSERT。
   真库 A/B 对照：保留→成功；去掉→`duplicate key`。
