## 三、本轮踩的坑（必看，下轮别重踩）

### 3.1 `pip install scenedetect` 会打挂平板上的 cv2

这是本轮最重要的坑，**我自己踩的，已修复**。

**现象链**：
```
pip install scenedetect==0.7.3
  → 顺带装 opencv-python（带 GUI 的完整版）
  → 平板容器无桌面，import cv2 报 ImportError: libxcb.so.1: cannot open shared object file
  → 卸载 opencv-python 后，import cv2 变成 ModuleNotFoundError（连 headless 也没了！）
```

**根因（两层）**：
1. `opencv-python` 需要 X11 图形库（`libxcb.so.1`），proot 容器没有桌面环境，装不上也跑不了。
2. `opencv-python` 与 `opencv-python-headless` **共用同一个 `cv2/` 目录**。卸载 GUI 版时，pip 把整个 `cv2/` 目录删了，而 headless 的包元数据还在 → `pip list` 显示已装，`import cv2` 却失败。

**修复方法（已验证有效）**：
```bash
# 1. 卸掉 GUI 版
pip uninstall -y opencv-python
# 2. 强制重装 headless（必须 --force-reinstall，否则 pip 误报"已安装"）
pip install --force-reinstall --no-deps opencv-python-headless
```

**复验结果**：`cv2 5.1.0` + `scenedetect 0.7.3` + `api ok` 三者共存正常。

**结论**：**永远不要在这个项目里装 `opencv-python`（GUI 版），只用 `opencv-python-headless`。**

### 3.2 `detect()` 便捷函数对纯色画面返回 0 个镜头

### 4.1 `scenedetect` 必须锁 0.6.6，不能锁 0.7.x —— ✅ 已独立证实

架构师的结论与交接文档（写的是 0.7.3）相反，我直接查了 PyPI 元数据核对：

```
--- scenedetect 0.6.6 ---
  Click / numpy / platformdirs / tqdm
  opencv-python; extra == "opencv"            ← 放在 extras 里，可不装
  opencv-python-headless; extra == "opencv-headless"

--- scenedetect 0.7.3 ---
  click / numpy / platformdirs / tqdm
  opencv-python                               ← 无条件依赖，必然装 GUI 版
```

**结论：架构师判断正确，交接文档写的 0.7.3 是错的（会把平板搞崩）。**

### 4.1b `FrameTimecode` 的 `.seconds` 是版本差异 —— ✅ 已查清，双方都没记错

这一点我和架构师的说法一开始对不上，核查后确认是**版本差异**，不是谁记错：

| 版本 | `.seconds` 属性 | `.get_seconds()` 方法 |
|---|---|---|
| **0.7.3**（本机实测） | ✅ 有（源码 `common.py:187` / `:400`） | ✅ 也有，但调用会报 `DeprecationWarning: use the seconds property instead` |
| **0.6.6**（架构师结论） | ❌ 没有 | ✅ 有 |

**下轮写代码的处理方式**：既然要降到 0.6.6，就不能直接用 `.seconds`，也不能只用 `.get_seconds()`（0.7.x 上会告警）。
写一个兼容小函数，两版都能跑：

```python
def _sec(tc) -> float:
    """FrameTimecode → 秒。0.6.6 只有 get_seconds()，0.7.x 推荐 .seconds。"""
    return float(getattr(tc, "seconds", None) or tc.get_seconds())
```

⚠️ 不要用 `getattr(tc, "seconds", 0.0)` 这种写法——0 秒是合法值，会被 `or` 吞掉。
上面写 `None or` 才能正确区分「没有该属性」与「值是 0」。

**模块划分**（照 `kb/asr/` 的两层形态）：

| 文件 | 职责 | 可单测 |
|---|---|---|
| `kb/vision/models.py` | 8 个 frozen dataclass + 1 个异常类 | 是 |
| `kb/vision/shot_plan.py` | 4 个纯函数：`plan_scan` / `merge_shots` / `plan_picks` / `is_blank` + `frame_filename` | 是（毫秒级） |

| `kb/vision/frames.py` | `extract_frames()` 装配 | 是（两个假实现） |

**六个关键设计判断**：

| 问题 | 结论 |
|---|---|
| 200 个镜头怎么裁 | **时间分层**：时间轴等分 K 层，每层取与之重叠最长的镜头，帧位取**交集中点**。不做全局 top-K（会把帧挤在少数长镜头），不做均匀抽（会抽到转场） |
| 0 个镜头（口播/静态画面） | **正常路径**，视为「整条视频一个镜头」。必须传 `get_scene_list(start_in_scene=True)`，否则静默变成零镜头 |
| 全黑帧过滤 | 用**灰度标准差 < 2.0** 判，不用平均亮度（会把暗但有内容的场景误杀） |
| 帧图尺寸 | 长边 **1024**、JPEG **q85**。不取 768 是因为字幕小字会糊到看不清 |
| 临时文件清理 | **本层不清理**，`FrameSet.work_dir` 交回调用方决定 |
| 超长视频 | `frame_skip` 控预算（实测切点数量不变、位置一致），`max_scan_sec=1800` 兜底 |

**另外三条实测发现**（都值得记住）：
- `cv2.imwrite` 对**中文路径静默失败**（返回 False 不报错）→ 必须用 `imencode` + 自己写文件。本项目路径就带中文。
- `cv2.VideoCapture` 要复用，每帧重开慢 **6.2 倍**（34.3ms vs 5.5ms/帧）。
- 抽帧位置取**镜头中点**不取起点（起点离切换边界太近，1 帧误差就落到前一镜头）。
