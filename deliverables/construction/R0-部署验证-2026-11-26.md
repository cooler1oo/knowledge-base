## 二、推翻了原设计的三个发现

### 2.1 Postgres 不能跑在 proot 里

| 尝试 | 结果 | 根因 |
|---|---|---|
| proot 内 `pg_createcluster 17 main` | ❌ `data directory has wrong ownership` | proot 的 UID 映射让 initdb 判定目录所有者不符 |
| proot 内 `su postgres -c initdb`（5 分钟） | ❌ 卡死 | 进程 `State: t (tracing stop)`，`wchan = ptrace_stop`。proot 的 ptrace 把 Postgres fork 出的 `postgres --check` 子进程永久停在跟踪态，永不恢复 |
| Termux 原生 `pkg install postgresql` | ✅ `Success` | Termux 的 PG 构建依赖 `libandroid-shmem`，是 Android 专用适配 |

**这一条推翻的是方案 v9.1 的 §2.2/§2.4/§7.3 三处**。修正后：Postgres 在 Termux 层，Python 服务在 proot 层，两层通过 `127.0.0.1:5432` 互通（已实测，proot 内 `psql` 成功连上，`current_user = u0_a201`）。

### 2.2 Postgres 版本从 17 变 18.7

Termux 仓库只提供 18.7。Debian 13 的 17.12 能装进 proot，但跑不起来（见 2.1）。两者相权取「能跑」的。

**影响评估**：DDL 已在 18.7 上逐条实跑，语法无差异。`jsonb`、`jsonb_path_ops`、`GENERATED ... STORED` 全部正常。

### 2.3 PG 原生检索兜不住中文搜索

在真机 PG 18.7 上跑了四种方案：

| 方案 | 结果 | 证据 |
|---|---|---|
| `pg_trgm` 的 `%` | ❌ 0 行 | `similarity('看完这篇你就懂了三体问题','三体') = **0.000**` |
| 阈值降到 0.05 | ❌ 仍 0 行 | 分数本身是 0，与阈值无关 |
| `simple` 分词 + `tsquery` | ❌ 0 行 | 中文整句当一个 token |
| `ILIKE '%三体%'` | ✅ 命中 | 但 `EXPLAIN` 显示 **`Seq Scan`**，GIN 索引用不上 |

**这改变了降级策略的权重**：Meilisearch 不是可选优化，而是中文搜索的必需件。§8.3 已据此重写。

### 2.4 Meilisearch 只能在 proot 里跑（ELF 实证）

**方案原写「Meilisearch aarch64 静态包」，这个描述是错的。** 通过下载分片的 ELF 头解析（不必等 335MB 下完）：

```
e_type:     0x3   ET_DYN (PIE)
e_machine:  0xB7  aarch64
PT_INTERP:  存在
解释器:     /lib/ld-linux-aarch64.so.1     ← glibc 动态链接器
```

**它是 glibc 动态链接的，不是静态包。**

三条证据链闭合：

| 证据 | 内容 |
|---|---|
| Termux 官方 Wiki | 「Dynamically linked programs from Linux distributions will not run」 |
| 本机实测（把容器内 glibc 二进制拷到 Termux 层执行） | `cannot execute: required file not found` |
| proot 内实测 | `/lib/ld-linux-aarch64.so.1` 存在（软链到 `aarch64-linux-gnu/`），`/bin/echo` 正常输出 `GLIBC_OK` |

**结论**：Meilisearch 与 kb-api / kb-worker 一样跑在容器里，同一个 supervisor 管。这不是「降级方案」，是唯一位置。

**顺带封死的另一条路**：Termux Wiki 明确「On non-rooted Android 8 or newer, statically linked programs will not run due to issues with seccomp」。所以「换静态版本」也不成立。

### 2.5 proot 内的进程必须由一个常驻会话托管（最难的一环）

**现象**：在 proot 里用 `nohup ... &` 或 `setsid` 起 Meilisearch，**当前 `proot-distro login` 会话一结束，进程立刻消失**。

```
$ proot-distro login debian -- bash -c "nohup ./meilisearch ... &"
$ # 会话退出后
$ pgrep meilisearch
（无输出）
$ ss -tln | grep 7700
未监听
```

只有两个 `proot --shm-helper` 残留在 PID 1 下。

**根因**：`proot-distro login` 用 `--kill-on-exit` 启动，会话结束时清理整棵子进程树。
- `nohup` 只挡 SIGHUP，挡不住进程树清理
- `setsid` 只脱离控制终端，改变不了「是该 login 会话后代」的事实

**正确做法**：让 supervisord 作为**常驻会话的前台主进程**：

```bash
proot-distro login debian -- bash -c 'exec /usr/bin/supervisord -c /etc/supervisor/supervisord.conf'
```

配置必须 `nodaemon=true`（daemonize 会自己脱离，同样被杀）。

**实测验证（从另一个 SSH 会话跨会话查询）**：

```
supervisord 存在    : YES
meilisearch 存在    : YES
health             : {"status":"available"}
```

**这条原设计完全没写**，是本轮最难发现的约束。

## 三、可复用的正确做法（下一轮直接用）

### 3.1 Termux 层（bionic）

```bash
pkg update -y && pkg install -y proot-distro openssh postgresql

# Postgres 初始化与启动
initdb -D $HOME/pgdata -E UTF8 --locale=C.UTF-8
# postgresql.conf 追加：
#   listen_addresses = '*'
#   port = 5432
#   shared_buffers = 128MB
#   max_connections = 20
# pg_hba.conf 追加：
#   host all all 0.0.0.0/0 trust
pg_ctl -D $HOME/pgdata -l $HOME/pg.log start
pg_isready -h 127.0.0.1 -p 5432
```

### 3.2 proot 容器内（glibc）

```bash
# Debian 用 Docker 镜像装（国内需走加速站）
proot-distro install docker.m.daocloud.io/library/debian:trixie --name debian

# apt 源（先 HTTP 装 ca-certificates，再切 HTTPS）
# /etc/apt/sources.list.d/debian.sources 内容见施工计划 R0
apt-get install -y python3 python3-venv python3-pip build-essential ca-certificates

# venv 与 parsehub
python3 -m venv /opt/kb-venv
/opt/kb-venv/bin/pip install parsehub
```

### 3.3 跨层连接（关键接缝）

proot 与 Termux 共享同一网络命名空间，`127.0.0.1:5432` 双向可达。**不需要**额外端口映射或 host 网络配置。

## 四、踩过的坑（按严重度排序）

| # | 坑 | 现象 | 正确做法 |
|---|---|---|---|
| 1 | **proot 内跑 Postgres** | `initdb` 卡死 5 分钟，`State: t (tracing stop)` | Postgres 装 Termux 原生层。这是架构级结论，不是参数问题 |
| 2 | **`exec_command` 前台跑长任务** | SSH 断开后进程卡死占锁，后续安装全失败 | 必须 `setsid nohup ... </dev/null &`，stdin 接 `/dev/null` 防止等输入 |
| 3 | **多层 shell 引号嵌套** | `sed: unterminated s command`、`SyntaxError: unexpected character after line continuation`。**连续失败 4 次** | 一律用 SFTP 写 `.sh` 文件，再 `bash file.sh` 执行。不要用 `bash -c "..."` 套引号 |
| 4 | **Termux 的 `/tmp` 不可写** | `Permission denied` | 日志一律写 `$HOME` |
| 5 | **Docker Hub 不可达** | `Network is unreachable` | 用 `docker.m.daocloud.io/library/debian:trixie` |
| 6 | **容器缺 CA 证书** | `certificate verify failed` | 先用 HTTP 源 `apt update` + 装 `ca-certificates`，再切回 HTTPS |
| 7 | **GitHub Release 极慢** | 直连 40 KB/s，335MB 需 143 分钟 | `ghfast.top` 前缀镜像，实测 154 KB/s（约 4 倍）。其他镜像 `ghproxy.net` 0 KB/s、`gh-llkk/ghproxy.cc/moeyy` 均 FAIL |
| 8 | **本机 SSH 端口耗尽** | `PermissionError: [WinError 10013]` | 本机短时间大量 paramiko 连接后触发。等几十秒再连，不要密集轮询 |
| 9 | **`pg_createcluster` 在 proot 下必失败** | `wrong ownership` | 已删除该路径，改 `pg_ctl` 直接管 `initdb` 创建的目录 |
| 10 | **`su postgres` 丢失 PATH** | `initdb: command not found` | 用绝对路径 `/usr/lib/postgresql/17/bin/initdb`（仅 proot 场景，现已不需要） |

## 六、下一轮入口（R0 收尾只剩一件事）

### G0'-7 重启恢复（唯一未跑的关卡）

boot 脚本已部署到 `$HOME/.termux/boot/00-kb-start.sh`，`bash -n` 语法检查通过。但它**不会自己触发**，因为 Termux:Boot 还没装。

**需要用户在平板上做两步**：

1. 下载并安装（0.7MB，走加速镜像）：
   ```
   https://ghfast.top/https://github.com/termux/termux-boot/releases/download/v0.8.1/termux-boot-app_v0.8.1%2Bgithub.debug.apk
   ```
2. 安装后**打开一次** Termux:Boot 的图标（Android 要求至少启动一次才注册 BOOT_COMPLETED 广播）

装完后由我执行：`reboot` → 等待 → 验证 PG / Meilisearch / health 三项自动恢复。

⚠️ **注意**：boot 脚本目前只起了 Postgres 和 supervisord。supervisord 的配置里目前只有 Meilisearch 一个 program（kb-api / kb-worker 还没写）。这是正常的，它们属于 R3+ 轮次。

### G0'-6 补测（可选）

zRAM 关闭状态下再测一次 `MemAvailable`，与当前 2.76GB 对比。需要用户手动关闭「内存扩展」。

补充：当前实测的服务总占用约 **134 MB**（PG 63 + Meilisearch 42.3 + supervisord 28.9），远低于原估算的 0.6–1.0 GB。zRAM 关闭后大概率仍远超 800MB 硬线，这一项优先级可以降低。
